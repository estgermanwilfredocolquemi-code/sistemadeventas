# Contribuir

Las contribuciones deben describir el problema que resuelven y mantener la documentación alineada con el comportamiento del programa.

1. Abre un Issue para registrar una tarea, defecto o decisión pendiente.
2. Crea una rama corta desde la rama principal acordada por el equipo.
3. Realiza un cambio acotado y compila con `dotnet build NexCodeSales.slnx`.
4. Actualiza requisitos o manuales cuando cambie el comportamiento.
5. Abre un pull request con el contexto, la verificación ejecutada y los pendientes.

Usa mensajes de commit descriptivos, por ejemplo `docs: explicar el flujo de venta` o `fix: validar cantidad disponible`. El equipo debe acordar cualquier formato obligatorio antes de automatizarlo.
